# Explainability

This document explains the inner workings, operational transparency, decision-making logic, data lineage, and limitations of the **AI-Adaptive Onboarding Engine** in compliance with the OpenGAP specification.

---

## How the Agent Decides

The AI-Adaptive Onboarding Engine evaluates candidates and generates personalized onboarding paths through a transparent, multi-stage decision pipeline. The agent does not operate as an unguided black box; each recommendation is traceable to explicit deterministic thresholds and verified semantic similarities.

### 1. Input Processing & Entity Extraction
- **Input**: The agent receives a candidate resume (PDF or raw text) and a target job description.
- **Text Layer Extraction**: The text is extracted deterministically using `PyPDF2`, normalizing unicode encoding, whitespace, and formatting anomalies.
- **Skill Entity Recognition**: The agent executes tokenization and syntactic chunking via `spaCy` and regular expression word-boundary filters (`\b<skill>\b`). It maps tokens against a standardized ontology of technical competencies, tools, and frameworks.
- **Experience Level Scoring**: The agent scans a bidirectional contextual window (-100 to +100 characters around each identified skill) for seniority markers (`senior`, `lead`, `architect`, `expert`, `built`, `years`).
  - Candidates with 2+ seniority indicators are tagged as **Advanced**.
  - Candidates with action-oriented development markers are tagged as **Intermediate**.
  - Candidates with baseline mentions are tagged as **Beginner**.

### 2. Decision Logic for Skill Gap Classification
The agent cross-references the candidate's extracted capabilities against the required skills from the job description using a two-tier evaluation mechanism:

1. **Exact & Normalized Matching**: Direct lexical equality against standardized O*NET identifiers.
2. **Semantic Vector Similarity**: For skill variations without exact lexical matches (e.g., `ReactJS` vs. `React Library`), the agent computes cosine similarity over high-dimensional dense vector embeddings generated by `sentence-transformers/all-MiniLM-L6-v2`:
   $$\text{Similarity}(v_{\text{req}}, v_{\text{cand}}) = \frac{v_{\text{req}} \cdot v_{\text{cand}}}{\|v_{\text{req}}\| \|v_{\text{cand}}\|}$$
   - **Matching Skill**: Exact match found, or semantic similarity $\ge 0.85$ with candidate experience tagged as Intermediate or Advanced.
   - **Weak Skill**: Lexical or semantic match exists ($\ge 0.85$), but candidate experience is classified as Beginner while the target role demands intermediate or advanced competency.
   - **Missing Skill**: No candidate skill meets the semantic similarity threshold of $0.85$ against the required skill.

### 3. Adaptive Roadmap Synthesis
For every identified gap, the agent formulates an adaptive, chronologically sequenced learning curriculum:
- **Upskill Modules**: For weak skills, the agent schedules targeted deep-dive modules (typically 2 weeks) emphasizing production architecture, best practices, and code reviews.
- **Foundational Modules**: For missing skills, the agent creates a two-phase pathway:
  - *Phase 1 (Foundations)*: 2 weeks covering syntax, core mental models, and foundational exercises.
  - *Phase 2 (Application)*: 3 weeks covering integration patterns, practical capstone projects, and real-world system design.
- **Dynamic Advice Generation**: When configured with an LLM inference endpoint (`mistralai/Mistral-7B-Instruct-v0.2`), the agent queries the model for personalized pedagogical coaching steps tailored specifically to the candidate's unique background.

## The Data It Uses

The agent relies upon validated public datasets and standardized occupational taxonomies to ground its decisions:

1. **O*NET (Occupational Information Network) Database**:
   - **Source**: U.S. Department of Labor / Employment and Training Administration (USDOL/ETA).
   - **Role**: Provides the standardized occupational ontology, role definitions, generalized work activities, and core knowledge domains.
   - **Application**: Used as the authoritative ground truth for standardizing skill naming conventions across varying industry descriptions.

2. **Kaggle Resume Dataset**:
   - **Source**: Sneha Anbhawal Resume Corpus (2,400+ categorized resumes across 24 industry sectors).
   - **Role**: Informs entity extraction patterns, structural resume segmentation (Experience, Education, Skills sections), and contextual experience keywords.
   - **Application**: Used to calibrate the -100 to +100 character contextual window heuristics to accurately detect experience levels.

3. **Kaggle Job Descriptions Dataset**:
   - **Source**: Kshitiz Regmi Jobs & Job Descriptions Corpus (10,000+ real-world tech and corporate postings).
   - **Role**: Provides statistical distributions of skill co-occurrences and frequency weighting for modern technical roles.
   - **Application**: Guides prioritization and sequencing in the roadmap generation logic.

4. **Dense Vector Embeddings**:
   - **Model**: `sentence-transformers/all-MiniLM-L6-v2`.
   - **Role**: Converts skill phrases into 384-dimensional dense vectors to calculate cosine similarity for semantic matching.

## Limitations

Users and evaluators should take note of the following technical and operational limitations:

### 1. Document Format & Scanned Media
- The agent extracts text from native, digital PDF documents.
- It does **not** perform Optical Character Recognition (OCR) on flattened, scanned, or photographic images of resumes. Resumes submitted as raster images will fail to yield extractable text.

### 2. Proprietary & Non-Standard Skills
- Emerging or internal proprietary corporate tooling not present in public taxonomies or O*NET datasets may fail exact matching. Such skills rely entirely on dense vector semantic similarity to identify related concepts.

### 3. Linguistic Proximity Heuristics
- The experience classification algorithm depends on textual proximity heuristics (e.g., proximity to words like "lead", "architect", "5 years"). Highly creative, infographic, or non-linear resume layouts may occasionally result in conservative experience estimations.

### 4. Natural Language & Cultural Scope
- The primary NLP tokenizers, semantic embeddings, and regex ontologies are calibrated for English-language resumes and job postings. Multilingual documents require localized semantic embedding models.

### 5. Decision Authority & Human-in-the-Loop
- The agent is designed strictly as a diagnostic accelerator and personalized educational planner.
- It does **not** make hiring, rejection, promotion, or compensation decisions. Human talent specialists, recruiters, and mentors must always review and approve generated roadmaps before organizational deployment.

### 6. Privacy & PII Handling
- The agent does not persist candidate personal data. All processing occurs ephemerally in memory during the request lifecycle, ensuring compliance with privacy standards such as GDPR and EEOC.
